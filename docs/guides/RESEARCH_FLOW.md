# 연구 흐름과 저사양 실행

## 연구 흐름

연구를 열고 **연구 흐름**을 선택합니다. 처음에는 **현재 작업**을 표시하며 **전체 연구 / 오류·복구 / 검증**으로 범위를 바꿀 수 있습니다.

- 다섯 줄은 연구 총괄, 자료·근거, 실험·분석, 검증·복구, 실행 도구의 논리적 역할입니다. 모델 프로세스 수를 뜻하지 않습니다.
- 노드를 선택하면 연결된 관계를 강조하고 오른쪽에 저장된 상세 기록을 불러옵니다. 방향키·Home·End로 이동하고 Enter로 선택합니다.
- F3-P는 원본 실패, 복구 결정, 새 수정본, 필수 재검증을 구분합니다. 예산 부족·검증기 실패·미해결 불일치는 완료로 표시하지 않습니다.
- 이전 수정본과 무효화된 결과는 유지합니다. 뒷받침·반증·제한·무효화·교체 관계도 구분합니다.

가로 위치는 저장된 의존 관계에 따른 순서입니다. 실제 실행 시간축이나 전체 완료율을 뜻하지 않습니다. 저장된 계획 버전이 없는 연구에 계획 버전·완료 백분율을 만들지 않습니다. 완료된 연구의 상태 조회는 자동 반복하지 않습니다.

## 실행 환경

**설정 → 고급 설정 → 성능 최적화**에서 선택합니다.

| 선택 | 동작 |
|---|---|
| 자동 · 추천 | 로컬에서 확인한 논리 CPU가 4개 이하 또는 RAM이 8GiB 이하이면 저사양 적용. 정보가 없으면 일반 적용 |
| 저사양 | 작은 조회 페이지, 제한된 동시 API 요청, 필요한 상세만 읽기 |
| 일반 | 큰 조회 페이지, 제한된 동시 API 요청 |

연구의 low / medium / high / max와 별도 설정입니다. 저사양에서도 high·max, 기존 검증·예산·자료 전송·Skills·F3-P 설정을 유지합니다.

동일 앱 DB를 사용하는 역할·연구·탭·프로필은 자원 대기열을 공유합니다. 서로 다른 로컬 서버를 포함해 추론은 1개, 무거운 분석은 1개, 원격 요청은 저사양 1개·일반 최대 4개이며 같은 원격 서버는 1개입니다. 대기 중에는 비용을 예약하거나 API를 보내지 않습니다. 대기열은 32개로 제한합니다.

Ollama·LM Studio 등은 사용자가 별도로 실행합니다. 앱에서 서버·가중치를 자동 실행하거나 종료하지 않습니다. 다른 DB의 앱 인스턴스나 외부 프로그램과의 자원 조정은 제공하지 않습니다.

## 실제 검증

앱 성능과 흐름도 검사는 고정 합성 자료·FakeProvider·Chrome으로 수행합니다. 로컬 모델의 토큰 속도·GPU 사용량이나 실제 API의 연구 성능을 증명하지 않습니다.
