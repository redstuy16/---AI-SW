# 실제 LUNA 과학 탐구 비교 검증

현재 앱의 자동 기본 출력은 판단·계획·AI 검색 최대 16,384토큰, 보고서 최대 32,768토큰이며 보고서 작성 전에 관련 검색을 시도합니다. 아래 비교 실험의 8,192토큰과 검색 없음 조건은 명시적으로 고정한 기존 실험 조건이며 현재 앱의 기본 동작을 뜻하지 않습니다.


프로젝트의 `Probe-과학검증.wsf`를 더블클릭하면 현재 Windows 사용자 세션에서 기존 앱 연결과 자격 증명을 사용합니다. API 키를 다시 등록하거나 관리자 권한을 사용할 필요가 없습니다. 결과 폴더가 열리고 `session.log`, `summary.json`, `report.md`, 연구별 `raw` 파일과 `sha256.json`에 진행 상황·원시 결과·해시를 저장합니다. 비밀값, 인증 헤더, 전체 입력 프롬프트는 결과 파일에 넣지 않습니다.

원본 `build/workbench/state.sqlite`는 SQLite `mode=ro`로 설정만 읽습니다. 연구와 원장은 새 `build/science-live/한국시간-세션ID` 폴더에 만들며, 전체 검증을 하나의 비용 원장으로 제한합니다. 이 검증 폴더의 이전 실제 세션까지 합친 전체 한도는 $3, 연구 한도는 $0.10, 연구당 시간은 300초입니다. 동일 원장 요청의 복제는 한 번만 합산하고 충돌 기록은 차단합니다. 운영체제 파일 잠금으로 중복 실행을 막고 이전 지출만큼 이번 세션의 원장 한도를 줄입니다. 재실행으로 $3 상한이 초기화되지 않습니다. 과금 불확실 요청이 생기면 다음 연구를 중단합니다.

앱 과학 루프의 기본 한도는 판단 6회·300초·진행 없음 2회입니다. 명시 설정은 판단 최대 20회·3600초·진행 없음 최대 5회까지 적용하며 다음 판단과 행동 경계에서 갱신합니다. 이 비교 실행기는 기본 한도를 고정해서 양쪽에 동일하게 사용합니다. 현재 시간 정책은 연구 시작부터의 경과 시간으로, 일시정지와 재개 사이 시간도 포함합니다.

다른 작업의 수정·전체 검사가 끝난 뒤 실제 비교를 실행합니다. 시작에 제품 소스와 모든 QA 코드의 해시를 고정하고, 모델 진입·자원 대기 종료 후 전송 직전·각 연구 완료·검색 출시 증빙 전에 대조합니다. 변경이나 읽기 실패를 감지하면 후속 호출과 통과 표식을 중단하고 `SOURCE_CHANGED` 또는 `SOURCE_GUARD_UNAVAILABLE` 이유와 기존 원 응답 사용량·원장·지출을 보존합니다. 중단한 비교를 속도·품질·검색 검증의 통과 근거로 사용하지 않습니다.

기존 `gpt-6-luna` 프로필의 추론·샘플링 설정과 검증된 가격을 사용합니다. 자격 증명을 현재 사용자 세션에서 읽지 못하면 `BLOCKED / CREDENTIAL_UNCONFIGURED`와 유료 요청 0회를 기록합니다. 연결·가격·출력 문맥 조건이 맞지 않아도 이유를 보존하고 보안 설정을 우회하지 않습니다.

자동 생성 기본 프로필만 비교 스냅숏에서 문맥 최소 131072 토큰·모델 입력 최소 128000 토큰·보고서 8192 토큰으로 보정합니다. 원본의 더 큰 문맥 상한은 유지합니다. 상세 설정에 직접 지정한 상한과 수동 프로필은 양쪽에서 그대로 보존하며 원본·실제 비교값·명시 설정 여부를 `inference_settings`에 기록합니다. 검색에 필요한 문맥보다 작은 명시 상한은 올리지 않고 해당 검색 사례를 이유와 함께 차단합니다. 이 정책은 검증용 스냅숏에만 적용합니다. 서버의 검색 도구가 사용하는 128000 토큰 상한은 실제 요청 전송 크기와 다른 단위이므로 원본 `input_byte_limit`는 유지합니다. 오프라인 경계 검사는 검색 입력 128000·출력 2048이 문맥에 맞는지만 확인하며 실제 가격·예산·지원 여부는 실행 중개기가 계속 검증합니다.

알려진 과학 원리, AI 문헌 검색, 합성 CSV의 세 사례를 앱과 단일 LUNA 방식으로 각각 세 번 수행합니다. 두 방식의 모델·자료·실제 출력 상한·결정론적 도구·검증·자체 검토 및 수정 기회는 같습니다. 자동 기본 출력은 8192이며 명시 상한은 보존합니다. 원본에 seed가 있다면 유지하며 없는 경우 재현 가능한 동일 모델 응답을 보장하지 않습니다. 두 번째 반복에서는 순서를 바꾸어 방식별 순서 영향을 줄입니다. 단일 방식은 앱의 판단 루프를 호출하지 않는 독립 실행기에서 하나의 manager가 행동 선택·검색·분석·자체 검토·수정을 수행합니다. 원장·native 검색·결정론적 도구·출처 및 보고서 검증만 공통으로 사용합니다. 같은 사례의 참고 예시는 첫 선정 내용을 모든 방식과 반복에서 고정합니다. 양쪽 모두 UTF-8 바이트/3의 보수적 추정과 예시 추가 1200토큰·남은 문맥 여유 100토큰 한도를 적용합니다. 모의 응답의 속도나 호출 수로 실제 모델 품질 우위를 판정하지 않습니다.

비용이 남으면 같은 원리 사례의 요청 출력 한도를 1024/4096/8192로 바꾸어 추가 비교합니다. 명시 사용자·모델 상한을 넘지 않도록 제한하며 요청값과 실제 적용값을 별도로 기록합니다. 연구·전체 예산은 바꾸지 않습니다. 총시간·첫 모델 결과·첫 보고서 시간, 실제 모델 API와 논리적 모델 작업 수, 검색·도구 호출, 토큰, 원장 지출, 실행 완료와 사례 요구 충족을 구분해서 기록합니다. 원리는 모델 작업 한 번과 검색 없음, 문헌은 실제 검색과 검증 인용, CSV는 두 검증 방법·비판 검토·실제 그림을 확인합니다. 합성 CSV에 제공되지 않은 단위·독립성은 검증했다고 표시하지 않습니다. 그림 파일 수와 도식 사양 수도 구분하며 `report.md`에서 실제 검증 그림과 원시 초안을 확인할 수 있습니다. 연구별 PDF·페이지 PNG·추출 텍스트를 `visual-quality`에 남기고 질문·도식·그림 순서/캡션·단위 공개·페이지 공백 여부를 객관 검사합니다. 작업 시간과 렌더 검사를 포함한 전체 시간, 첫 검증 보고서와 첫 PDF 시각을 구분합니다. 객관 검사 실패나 검사기 미지원은 비교 완주로 표시하지 않습니다. 내용·과학적 의미·시각 설명력의 품질은 `HUMAN_REVIEW_REQUIRED`, 우위는 `NOT_ASSESSED`로 두고 사람이 검토해야 합니다.

네트워크와 키 조회 없이 실행기를 점검하려면 다음 명령을 사용합니다.

```powershell
.\.venv\Scripts\python.exe -B -X utf8 qa/science_live_validation.py --smoke
```

실제 검증을 명령으로 실행할 때는 `--smoke` 대신 `--live --open-results`를 사용합니다. 모의 검증은 알려진 원리의 작업 한 번, 실제 CSV 계산·민감도 검사·검토·그림, 문헌 미확보 시 중단, 독립 단일 LUNA의 자체 검토와 같은 참고 예시 고정과 유료 호출 없음을 확인합니다. 모의 검증 성공은 실제 API·문헌 검색 품질·유료 모델 속도 검증을 의미하지 않습니다.

실제 문헌 사례 여섯 건이 모두 요구를 충족하고 검색 응답·action 수·실사용량·정산 원장이 원시 해시와 맞을 때만 `build/validation/search.json`을 native 검색 통과로 갱신합니다. 모의 실행·자격 증명 차단·문헌 실패·미정산이 있으면 기존 표식을 쓰지 않으며 현재 결과의 `native_search_validation`은 통과로 표시하지 않습니다.
