# 제출 상태 정리

제출 실행 경로는 `Probe-제출.wsf` 또는 `python -m probe.desktop --submission`이다. 저장소의 가상환경에서 실행하며, 고정 CSV·모의 응답으로 분석·검증·보고서·PDF를 만든다. `build/submission-demo/`에 예시를 저장하고 검증된 예시를 재사용한다. 예시 화면은 조회와 PDF 다운로드를 제공한다.

## 실행을 막던 조건의 정리

- 설치 조건을 Python 3.12 이상으로 맞추고 필수 PDF 의존성 `pypdf`를 기본 설치에 포함했다. 앱과 자식 실행기는 같은 가상환경으로 사전점검한다.
- 과학 모드는 시작에 필요한 역할을 먼저 검사하고, 다른 역할은 실제 요청 시 검사한다. 역할별 문맥 한도를 적용하고 전용 분석 절차의 선택이 일반 과학 연구를 막지 않도록 분리했다. 실제 요청의 가격·동의·예산·비용 검사는 유지한다.
- 실패한 연구는 새 요청 키로 명시적으로 다시 시작할 수 있다. 사전점검은 DB 쓰기 잠금 밖에서 수행하고, 점검 중 입력이 바뀌면 실행을 차단한다.
- 워커 준비 중 소유자와 실행 시작 값을 기록한다. 복구와 PID 확인이 완료 상태를 덮어쓰지 않도록 하고, 실제 종료를 확인한 계산만 자원을 회수한다. 종료 여부가 불확실하면 실행 차단을 유지한다.
- 자격 증명 저장소를 요청 처리 전에 확인한다. Docker CLI에는 연결 설정에 필요한 환경만 추가하며 제공사 키는 전달하지 않는다.
- 이전 보고서가 손상돼도 보존한 채 새 수정본을 검증·발행할 수 있다. 종료 연구의 원문 무효화와 근거 요약은 원자적으로 저장한다. 무효 자료만 남았으면 모델 호출 없이 한계 보고서를 만든다.
- 보고서 배치의 차단·실패 항목은 명시적 재개 시 새 키로 재시도한다. 완료 작업은 재사용하고 입력 변경·미확정 비용은 계속 차단한다.
- 제출 예시의 선택 실험 기능과 초기 설정 튜토리얼은 끈다. 연구 생성·재작성·내보내기 등의 쓰기 API를 차단하고 해당 버튼을 숨긴다. 실제 모델 연구는 `Probe.wsf`의 기존 설정 흐름을 사용한다.

## 확인한 범위

- 실행기 사전점검 `READY`, Python 소스 문법 검사와 JavaScript 문법 검사 통과, `pip check` 오류 없음.
- Windows Edge에서 자동 로컬 인증 → 연구 목록 → 개요 → 보고서 PDF 표시 → 다운로드를 확인했다. 화면의 모의 응답 표시, 외부 요청 없음, JavaScript 오류 없음, 제출 범위의 쓰기 버튼 비노출을 확인했다.
- PDF 5페이지를 렌더링해 확인했고 내려받은 PDF도 읽을 수 있다.
- 회귀 검사에는 실패 후 재시도, 사전점검 중 입력 변경, PID 재사용, 완료 직후 복구, 종료 미확정 자원, 손상 보고서 교체, 원문 무효화의 롤백, 예산 차단 배치 재개, 미확정 비용 보존, 예시 재사용을 포함한다. 전체 실행은 1,687개 통과·구식 내부 토큰 단언 5개 실패로 끝났다. 해당 단언을 고친 재검사 5개와 현재 계산·실행 정책 재검사 146개가 통과했다. 결과를 합쳐 현재 선택되는 오프라인 1723개 사례 모두를 확인했으며 미검사·미통과 사례는 없다. 전체를 다시 실행한 단일 통과 기록으로 표시하지 않는다. 원본 기록은 `build/submission-fix/offline-final.xml`, `frozen-relevance-fixed.xml`, `latest-science.xml`, 집계는 `verification-final.json`에 보존한다.
- 실제 API·외부 검색·Docker 실행과 CP949 환경 별도 검증은 `NOT_VALIDATED`이다. 제출 예시는 해당 환경을 요구하지 않는다. 공개 준비 검사의 라이선스와 정식 회귀 검증 표시를 임의로 통과시키지 않았다.
