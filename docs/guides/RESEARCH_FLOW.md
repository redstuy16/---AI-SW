# 연구 흐름과 저사양 실행

## 연구 흐름

연구는 검색 가능한 카드 목록에서 엽니다. 기본 탭은 **개요**입니다. 상단 상태 배지, 사용 비용·남은 예산, 실행 버튼과 7개 탭을 모든 연구가 공유합니다. 제목은 목록과 상단에서 두 줄로 표시하며 **전체 제목**으로 펼칠 수 있습니다.

**연구 흐름**은 실제 Agent 작업과 자료·분석·검증의 관계를 노드로 바로 표시합니다. 왼쪽 첫 범주는 **전체 연구**이며, **자료·근거 / 실험·분석 / 검증·복구 / 실행 도구**로 범위를 바꿉니다. 그래프 아래에는 현재·마지막·다음 작업, 확인할 항목과 최근 5개 이벤트가 있습니다.

그래프의 **전체 연구 / 현재 작업 / 오류·복구 / 검증**으로 표시 범위를 바꿉니다. 실제 저장된 Agent 호출은 완료된 작업까지 기본으로 펼쳐 보여줍니다. 역할 구역의 버튼으로 호출 기록을 접거나 펼칠 수 있습니다.

- 다섯 줄은 연구 총괄, 자료·근거, 실험·분석, 검증·복구, 실행 도구의 논리적 역할입니다. 모델 프로세스 수를 뜻하지 않습니다.
- 노드를 선택하면 연결된 관계를 강조하고 오른쪽에 저장된 상세 기록을 불러옵니다. 방향키·Home·End로 이동하고 Enter로 선택합니다.
- F3-P는 원본 실패, 복구 결정, 새 수정본, 필수 재검증을 구분합니다. 예산 부족·검증기 실패·미해결 불일치는 완료로 표시하지 않습니다.
- 이전 수정본과 무효화된 결과는 유지합니다. 뒷받침·반증·제한·무효화·교체 관계도 구분합니다.

가로 위치는 저장된 의존 관계에 따른 순서입니다. 실제 실행 시간축이나 전체 완료율을 뜻하지 않습니다. 저장된 계획 버전이 없는 연구에 계획 버전·완료 백분율을 만들지 않습니다. 진행 중 상태는 10초 간격으로 갱신하며 기존 노드·스크롤·선택·PDF 위치를 보존합니다. 완료된 연구의 단계 조회는 자동 반복하지 않습니다. 비용은 기존 5초 갱신을 사용합니다.

색과 텍스트를 함께 표시합니다. 완료는 초록, 진행은 파랑, 대기는 회색, 확인 필요는 주황, 실패는 빨강입니다. **설계안 완료**와 **재검증 필요**를 측정 성공으로 표시하지 않습니다. 상단은 공식 전체 상태이고 노드는 저장된 개별 작업 상태입니다. 진행 기록은 저장된 의사결정·도구·검증 기록이며 모델의 내부 사고 과정은 표시하지 않습니다.

읽기 전용 GET /api/control/research/{id}/screen은 기존 상태·비용·근거·검증 기록을 요약합니다. 기존 execution-summary, 상세 조회, 보고서·PDF·내보내기 API와 /flow, /timeline 주소를 유지하며 과거 진행 주소는 같은 통합 화면으로 연결합니다.

## 실행 환경

**설정 → 고급 설정 → 성능 최적화**에서 선택합니다.

| 선택 | 동작 |
|---|---|
| 자동 · 추천 | 로컬에서 확인한 논리 CPU가 4개 이하 또는 RAM이 8GiB 이하이면 저사양 적용. 정보가 없으면 일반 적용 |
| 저사양 | 작은 조회 페이지, 제한된 동시 API 요청, 필요한 상세만 읽기 |
| 일반 | 큰 조회 페이지, 제한된 동시 API 요청 |

연구의 low / medium / high / max와 별도 설정입니다. 저사양에서도 high·max, 기존 검증·예산·자료 전송·Skills·F3-P 설정을 유지합니다.

동일 앱 DB를 사용하는 역할·연구·탭·프로필은 자원 대기열을 공유합니다. 서로 다른 로컬 서버를 포함해 추론은 1개, 무거운 분석은 1개, 원격 요청은 저사양 1개·일반 최대 4개이며 같은 원격 서버는 1개입니다. 대기 중에는 비용을 예약하거나 API를 보내지 않습니다. 대기열은 32개로 제한합니다.

Ollama·LM Studio 등은 사용자가 별도로 실행합니다. 앱에서 서버·가중치를 자동 실행하거나 종료하지 않습니다. 다른 DB의 앱 인스턴스나 외부 프로그램과의 자원 조정은 제공하지 않습니다.

## 실제 검증

앱 성능과 흐름도 검사는 고정 합성 자료·FakeProvider·Chrome으로 수행합니다. 로컬 모델의 토큰 속도·GPU 사용량이나 실제 API의 연구 성능을 증명하지 않습니다.
