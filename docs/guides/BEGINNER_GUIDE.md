# H-TRSA 사용 안내

안내 버전: 4 · 공식 문서 확인: 2026-10-04

화면의 튜토리얼·사용 안내와 같은 원본에서 생성한다. 참여 선택 팝업에서 보기를 선택하면 실제 화면의 입력칸·버튼을 화살표와 안내 상자로 가리킨다. API 발급은 선택한 제공사의 절차를 자세히 읽고, 나머지는 실제 화면에서 따라 한다.
학습 완료는 핵심 안내를 읽었다는 뜻이며 실제 API·Agent 성능·출시 검증과 별개다.

## 핵심 튜토리얼 — 4단계

### 1. 제공사별 API 키 발급

선택한 제공사의 계정·결제·키 발급 순서를 확인합니다.

1. 사용할 제공사의 공식 화면에서 API 키를 발급받습니다.
2. 복사한 키를 준비하고 앱 연결 안내로 이동합니다.

### 2. 앱에 API 연결

앱의 연결 화면에 API 키를 입력하고 저장합니다.

1. API 키·연결 이름·전송 동의를 확인합니다.
2. 연결 저장을 직접 누릅니다. 실제 응답 확인은 별도의 유료 검사입니다.

### 3. 새 연구 만들기

연구 화면의 새 연구 만들기 버튼을 직접 누릅니다.

1. 연구 화면으로 이동합니다.
2. 화살표가 가리키는 새 연구 만들기를 누릅니다.

### 4. 연구 설정 항목 입력

주제·질문·파일 → 모델·성능·검색·예산 → 시작 전 확인 순서로 작성합니다.

1. 입력칸 옆의 안내를 따라 연구 설정 3장을 작성합니다.
2. 시작 전 설정과 금액을 확인하고 연구 시작을 직접 누릅니다.

자세한 발급·오류 해결·고급 기능은 아래 사용 안내에서 찾아본다.

## 시작할 때 선택

튜토리얼 보기

API 키 준비부터 연구 시작까지 화면에서 따라 해 볼까요?

- 튜토리얼 보기: 튜토리얼을 실행한다.
- 건너뛰기: 이번 실행에서 건너뛴다.
- 다시 보지 않기: 다음 시작부터 묻지 않는다.

설정 → 도움말 및 안내에서 언제든 다시 볼 수 있습니다.

## 화살표와 안내 상자

입력칸·버튼을 한 번에 하나씩 가리킨다. 안내 이동으로 키 입력·연결 검사·유료 연구를 자동 실행하지 않는다.

### API 키 준비

- 제공사를 고르고 API 키를 준비하세요.

### 앱에 API 연결

- API 키를 저장할 연결 화면을 여세요.

### API 연결

- 발급받은 API 키를 이 칸에 붙여 넣으세요.
- 알아보기 쉬운 연결 이름을 적으세요.
- 선택한 제공사로 자료를 보내는 데 동의하는지 확인하세요.
- 직접 눌러 연결과 키를 저장하세요. 연결됨·활성화 표시와 실제 API 응답 확인은 별도입니다.

### 로컬 서버 연결

- 실행한 로컬 서버의 주소를 입력하세요.
- 로컬 서버의 연결 이름을 적으세요.
- 서버 설정을 저장하세요.

### 새 연구 만들기

- 이 버튼을 눌러 새 연구 설정을 여세요.

### 연구 화면으로 이동

- 연구 탭에서 새 연구 만들기를 누르세요.

### 주제와 자료

- 일반 설정과 맞춤 연구 설계 중 원하는 방식을 선택하세요. 선택한 방식으로 안내합니다.
  어떤 방식으로 연구를 설정할까요? 일반 설정은 질문과 자료를 간단히 넣고, 맞춤 연구 설계는 목적·비교 조건·측정할 값까지 직접 정합니다. 원하는 방식을 선택한 뒤 다음 안내를 누르세요.
- 연구를 알아볼 수 있는 제목을 적으세요. 예: 온도와 식물 성장.
- 확인할 내용을 질문으로 적으세요. 예: 온도와 성장량은 관련이 있나요?
- 연구에 필요한 파일이 있으면 넣어 주세요. 파일이 없어도 질문을 입력해 시작할 수 있습니다.
- 주제·질문·자료를 확인했으면 다음 장을 누르세요.

### 모델과 비용

- 초록색 활성화 모델을 고르세요. 빨간색 비활성화 모델은 API 연결이 필요합니다.
- low는 적은 작업, medium은 기본, high·max는 더 많은 검토입니다. 높을수록 비용이 늘 수 있습니다.
- 자동은 필요할 때, 허용은 검색을 허용, 사용 안 함은 검색하지 않습니다. 검색비는 모델비와 별도입니다.
- 찾고 싶은 논문의 핵심 단어를 적으세요. 예: 식물 성장 온도 영향. 아래 입력 예시도 확인하세요.
  찾고 싶은 논문의 핵심 단어를 적으세요. 예: 식물 성장 온도 영향, 또는 plant growth temperature. 문장 전체보다 주제·대상·비교 조건을 짧게 쓰면 좋습니다. 검색어는 외부로 보내므로 이름이나 비공개 자료는 넣지 마세요. 웹 검색을 사용하지 않으면 비워 두어도 됩니다.
- 이 검색어를 외부 검색 서비스로 보내는 데 동의할 때만 체크하세요.
- 이번 연구의 최대 금액을 USD(미화 달러)로 입력하세요. 0.10은 0.10달러입니다.
  이번 연구에서 쓸 최대 금액을 USD(미화 달러)로 입력하세요. 예: 0.10은 0.10달러입니다. 제공사 계정의 잔액과 앱의 연구 예산은 따로 확인하세요.
- 켜 두면 예산에 맞춰 작업과 검색 횟수를 줄입니다. 설정한 상한을 임의로 늘리지 않습니다.
- 사용할 모델과 이번 연구의 최대 금액을 확인하고 다음 장을 누르세요.

### 시작 전 확인

- 고급 설정은 건너뛰어도 됩니다. 역할·추론·검증은 필요한 경우에만 변경하세요.
- 기본값은 질문과 선택한 분석 자료를 함께 보내기입니다. 바꾸려면 고급 설정을 펼치세요.
- 표시된 최대 금액과 전송 범위를 확인한 뒤 직접 누르세요. 이 버튼부터 유료 API 요청이 시작됩니다.

### 연결 확인

- 모델과 예산을 확인한 뒤 직접 연결을 검사하세요.

### 이어서 보기

- 여기를 눌러 튜토리얼을 이어 보세요.

### 맞춤 연구 설계

- 일반 설정과 맞춤 연구 설계 중 원하는 방식을 선택하세요. 선택한 방식으로 안내합니다.
  어떤 방식으로 연구를 설정할까요? 일반 설정은 질문과 자료를 간단히 넣고, 맞춤 연구 설계는 목적·비교 조건·측정할 값까지 직접 정합니다. 원하는 방식을 선택한 뒤 다음 안내를 누르세요.
- 이 연구를 알아보기 쉬운 제목을 적어 주세요. 예: 온도에 따른 식물 성장.
- 가장 알고 싶은 내용을 질문으로 적으세요. 예: 온도가 다르면 식물의 성장량도 달라질까요?
- 연구에 필요한 파일이 있으면 넣어 주세요. 파일이 없어도 질문을 입력해 시작할 수 있습니다.
- 어떻게 알아볼지 고르세요. 아직 정하지 않았다면 자동 선택을 그대로 두어도 됩니다.
  어떻게 알아볼지 고르세요. 이미 있는 자료를 살펴보거나 직접 측정할 수 있습니다. 아직 정하지 않았다면 자동 선택을 그대로 두세요.
- 이 연구로 무엇을 알고 싶은지 적으세요. 예: 식물이 잘 자라는 온도를 알아보고 싶다. 모르는 항목은 비워 두어도 됩니다.
- 비교하거나 측정할 항목을 적으세요. 예: 온도, 식물의 키. 같게 유지할 조건이 있다면 물의 양처럼 추가하세요.
- 살펴볼 대상과 기간을 정했다면 이 항목을 펼쳐 적으세요. 예: 식물 20개를 4주 동안 관찰.
- 측정 순서와 방법을 정했다면 펼쳐 적으세요. 예: 매일 같은 시간에 키를 재고 기록한다.
- 사용할 분석 방법을 알고 있다면 적으세요. 잘 모르겠다면 비워 두어도 됩니다. 지원하지 않는 방법은 바로 실행되지 않습니다.
- 결과를 볼 때 꼭 확인할 조건이나 한계가 있으면 적으세요. 예: 이 자료만으로 원인을 단정하지 않는다.
- 입력 내용 확인을 눌러 서로 다른 기간이나 조건이 섞이지 않았는지 살펴보세요. 이 확인에는 API 비용이 들지 않습니다.
- 아는 항목을 작성했으면 다음 장에서 모델과 비용을 정하세요.

## 1. 앱 이해하기

### 연구가 어떻게 진행되나요?

**준비물**

- 확인하고 싶은 질문을 준비하세요.

**실제 조작**

1. 도움말에서 API 키 준비와 앱 연결 순서를 확인하세요.
2. 연구는 질문 작성 → 자료 확인 → 분석 → 검토 → 보고서 순서로 진행됩니다.
3. API 키가 준비되면 앱에 연결하고 새 연구를 만드세요.

**입력 예시**

온도와 성장량의 관계를 분석하되 원인이라고 단정하지 않는 연구입니다.

**정상 결과**

- 연구에 필요한 준비와 진행 순서를 알 수 있습니다.

**문제가 생겼을 때**

- API를 처음 쓴다면 API 키 발급 안내부터 읽어 주세요.
### API·키·모델은 무엇인가요?

**준비물**

- 사용할 AI 제공사를 하나 정합니다. 나중에 추가하거나 바꿀 수 있습니다.

**실제 조작**

1. API는 이 앱이 AI 회사의 서비스에 요청을 보내는 통로입니다.
2. API 키는 그 요청을 내 계정으로 허용하는 비밀값입니다. 로그인 비밀번호와 다릅니다.
3. 제공사는 서비스를 운영하는 회사, 모델은 실제 질문을 처리하는 AI의 종류입니다.
4. 앱을 쓰는 데 코딩이나 별도 SDK 설치는 필요하지 않습니다.

**입력 예시**

제공사 OpenAI → 그 계정에서 발급한 API 키 → 앱의 OpenAI 모델 선택

**정상 결과**

- 같은 제공사의 키와 모델을 짝지어 사용할 수 있습니다.

**문제가 생겼을 때**

- ChatGPT·Claude 등의 챗봇 구독만으로 API 이용 조건이 충족되는지는 API 계정의 결제·권한 화면에서 확인하세요.
### 화면과 조작 익히기

**준비물**

- 브라우저에서 H-TRSA가 열려 있어야 합니다.

**실제 조작**

1. 왼쪽 메뉴에서 연구, 자료 보관함, 사용량, 설정을 이동합니다.
2. 설정 안의 AI 연결·예산·성능 최적화·도움말 탭을 사용합니다.
3. 슬라이더는 손잡이를 끌거나 키보드 방향키로 조절합니다.
4. 목차로 필요한 단계에 바로 가거나 상단 도움말에서 설명을 검색할 수 있습니다.

**입력 예시**

처음에는 API 준비 → 연결 → 새 연구 순서로 읽습니다.

**정상 결과**

- 안내를 닫아도 도움말과 튜토리얼 버튼에서 이어 볼 수 있습니다.

**문제가 생겼을 때**

- 앱에 연결할 수 없다는 화면이면 H-TRSA를 다시 실행해 인증된 로컬 창을 열어 주세요.

## 2. API 준비하기

### 제공사 계정과 결제 준비

**준비물**

- 위에서 사용할 제공사를 선택합니다. 로컬 서버는 별도 안내를 선택합니다.

**실제 조작**

1. 선택한 제공사의 공식 계정 화면을 엽니다. 처음이라면 가입, 계정이 있다면 로그인을 선택합니다.
2. 제공사 화면에서 이메일·로그인 방법을 선택하고 필요한 이메일 인증·약관 확인을 마칩니다. 앱에는 계정 비밀번호를 입력하지 않습니다.
3. API 프로젝트·팀·작업 공간을 확인합니다. 회사 계정이면 모델·키 발급 권한이 있는지 관리자에게 확인합니다.
4. Billing·결제·Credits·잔액처럼 표시된 API 이용 항목에서 결제 상태·사용 한도를 확인합니다. 화면 이름과 이용 조건은 제공사·계정별로 다를 수 있습니다.
5. 키 발급과 모델 사용 권한이 준비되면 다음 단계로 갑니다. 키를 발급했다고 잔액·모델 접근 권한까지 자동 준비되는 것은 아닙니다.
6. 결제나 충전은 제공사 화면에서 요금을 확인한 뒤 직접 진행하세요.

**입력 예시**

처음에는 한 제공사만 연결하세요. 튜토리얼에서 결제하거나 자동 요청을 보내지는 않습니다.

**정상 결과**

- 내 계정의 API 관리 화면에 접근할 수 있고, 이용 조건을 확인합니다.

**문제가 생겼을 때**

- 가입이나 결제가 안 된다면 아래 추가 안내에서 지역·계정 조건을 확인하세요.
### API 키 발급하고 복사하기

**준비물**

- 선택한 제공사의 계정·프로젝트에 로그인해 두세요.

**실제 조작**

1. 아래 ‘API 키 발급 화면’을 열어 선택한 제공사의 키 관리로 이동합니다.
2. 키 생성 버튼을 누르고 H-TRSA처럼 알아보기 쉬운 이름을 붙입니다.
3. 필요한 모델을 사용할 권한을 선택합니다. 프로젝트가 있다면 연구용 프로젝트를 선택합니다.
4. 완성된 키의 복사 버튼을 누른 뒤 이 앱의 연결 화면에 붙여 넣습니다.

**입력 예시**

키 이름: H-TRSA 개인 연구. 키 원문은 이 안내에 입력하지 않습니다.

**정상 결과**

- 키는 앱의 API 키 입력칸에만 붙여 넣습니다. 안내 화면은 키를 수집하지 않습니다.

**문제가 생겼을 때**

- 키가 다시 보이지 않으면 새 키를 발급하세요. Gemini에서 프로젝트 권한이 없으면 관리자에게 키 생성 권한을 요청하세요.
### 키를 잃어버리거나 바꿔야 할 때

**준비물**

- 제공사의 키 관리 화면과 앱의 AI 연결 위치를 확인합니다.

**실제 조작**

1. 키는 비밀번호처럼 관리하고 질문·첨부·공개 문서에 넣지 않습니다.
2. 잃어버린 키는 제공사에서 새로 발급한 뒤 앱의 키 교체로 저장합니다.
3. 노출된 키는 제공사에서 즉시 사용 중지 또는 폐기하고 사용량을 확인합니다.
4. 앱에서 연결이나 로컬 키를 삭제하는 것과 제공사의 키 폐기는 별도 작업입니다.

**입력 예시**

키 원문 대신 ‘내 OpenAI 연결’처럼 연결 이름으로 구분합니다.

**정상 결과**

- 새 키를 저장한 후 모델을 골라 직접 연결을 확인합니다. 기존 키는 다시 표시되지 않습니다.

**문제가 생겼을 때**

- SECRET_ 오류가 나오면 안내의 ‘키 저장 실패’를 참고하세요. 원문 키를 오류 보고에 첨부하지 않습니다.

## 3. 앱에 연결하기

### 앱에 API 연결 저장하기

**준비물**

- 제공사에서 복사한 키를 준비합니다. 로컬 무인증 서버는 키가 필요 없습니다.

**실제 조작**

1. ‘이 화면 열기’를 눌러 설정의 AI 연결 화면으로 이동합니다.
2. AI 연결하기 → 제공사 선택 → API 키 붙여 넣기 → 연결 이름 확인 순서로 입력합니다.
3. 선택한 제공사로 전송하는 설정을 확인한 뒤 연결 저장을 누릅니다.
4. 클라우드 제공사의 주소는 자동 입력됩니다. 고급 주소를 따로 바꾸지 않아도 됩니다.
5. API 키를 앱에 입력해 저장하면 됩니다. 처음 사용하는 경우 .env 파일을 직접 만들거나 고급 설정의 환경변수를 바꿀 필요가 없습니다.

**입력 예시**

연결 이름: 내 OpenAI. API 키는 암호 입력칸에만 입력합니다.

**정상 결과**

- 초록색 저장 알림과 연결 목록이 나타납니다. ‘연결됨’은 키·설정 준비 상태이며 실제 API 응답 검사 통과를 뜻하지 않습니다.

**문제가 생겼을 때**

- 키 저장 실패 시 새로 발급한 키를 재입력하고 키 저장 실패 안내를 읽어 주세요. 로컬 서버는 아래 설치·실행 순서를 확인하세요.
### 사용할 모델 먼저 선택하기

**준비물**

- 앱에 같은 제공사의 연결이 저장되어 있어야 합니다.

**실제 조작**

1. 새 연구를 열고 주제·질문을 입력한 뒤 다음 장으로 이동합니다.
2. 모델과 예산 화면에서 초록색 ‘활성화’인 모델을 선택합니다.
3. 상단 5개 외의 모델은 더보기에서 제공사별로 찾습니다.
4. 선택한 모델이 연결에 등록되면 연구를 시작하지 않고 창을 닫아도 됩니다. 작성한 초안은 보존됩니다.

**입력 예시**

처음에는 활성화된 모델 한 개와 medium을 선택하세요.

**정상 결과**

- 모델 선택이 저장되고 해당 연결의 AI 연결 확인에서 선택할 수 있습니다.

**문제가 생겼을 때**

- 비활성화만 보이면 선택한 제공사의 연결·키·연결 사용·전송 설정을 확인하고 새 연구를 다시 열어 주세요.
### 실제 API 응답 확인하기

**준비물**

- 앞 단계에서 모델을 먼저 선택해 등록합니다. 제공사 이용 조건과 앱 예산을 확인합니다.

**실제 조작**

1. 설정 → AI 연결 → 해당 연결의 AI 연결 확인을 누릅니다.
2. 검사할 모델과 버튼에 표시된 비용 상한을 확인합니다.
3. 실제로 검사하려면 본인이 ‘AI 연결 확인 · 최대 $0.10’을 누릅니다. 튜토리얼의 다음 버튼은 요청을 보내지 않습니다.
4. 검사 결과를 읽고, 실패하면 아래 문제 해결 안내로 이동합니다.

**입력 예시**

연결 검사는 짧은 고정 질문을 보냅니다. 내 연구 질문·파일은 보내지 않습니다.

**정상 결과**

- ‘연결 확인 완료’가 나타나면 해당 검사 요청의 성공을 확인한 것입니다. 전체 연구의 성능을 보장하지 않습니다.

**문제가 생겼을 때**

- 401은 키·프로젝트를, 403은 계정·모델 권한을 확인합니다. 429는 잔액 부족과 일시적 요청 제한을 구분합니다.

## 4. 연구 입력하기

### 주제와 질문 작성하기

**준비물**

- 무엇을 알아볼지 한 가지를 정합니다. 파일이 없어도 입력할 수 있습니다.

**실제 조작**

1. 연구 목록의 새 연구 만들기를 누릅니다.
2. 주제에는 목록에서 알아보기 쉬운 이름을 적습니다.
3. 질문에는 비교 대상·기간·측정값·단위를 함께 적습니다.
4. 한 번에 여러 문제를 묻기보다 첫 질문을 좁혀 주세요.

**입력 예시**

주제: 두 기간의 기온 비교
질문: 1981~2000년과 2001~2020년의 전 지구 연간 기온 편차 평균을 비교해 주세요.

**정상 결과**

- 주제·질문을 유지한 채 다음 장으로 이동합니다. 지원하지 않는 분석은 필요한 자료와 방법을 안내합니다.

**문제가 생겼을 때**

- 질문이 비어 있으면 다음 장으로 갈 수 없습니다. 직접 자료를 사용할 때는 자료의 열 이름·단위를 질문과 맞춰 주세요.
### CSV와 참고 파일 선택하기

**준비물**

- 개인정보·키를 제외한 분석 자료를 준비합니다.

**실제 조작**

1. 파일 찾아보기를 눌러 컴퓨터의 자료를 선택합니다. 여러 파일을 추가할 수 있습니다.
2. CSV는 첫 줄에 열 이름이 있고 이후 줄에 값이 있는 UTF-8 표로 준비합니다.
3. 업로드 목록에서 ‘내용 읽기 완료’인지 확인하고 불필요한 파일은 제거합니다.
4. CSV 분석 자료와 PDF·텍스트 참고 자료의 분석 가능 범위를 구분합니다.

**입력 예시**

CSV 예시:
temperature,growth
10,2
12,3
14,5

**정상 결과**

- 목록에 파일 이름과 처리 상태가 표시됩니다. 장을 바꾸거나 창을 다시 열어도 초안 첨부가 유지됩니다.

**문제가 생겼을 때**

- 파일당 5MB, 한 번에 10개·합계 20MB 한도를 확인하세요. 실행 파일·HTML·SVG는 차단됩니다. 읽기 실패 파일은 형식·인코딩을 확인하거나 제거합니다.
### 어떤 자료가 외부로 전송되나요?

**준비물**

- 보낼 자료에 개인정보·계정 비밀이 없는지 확인합니다.

**실제 조작**

1. 고급 설정의 전송 범위를 확인합니다.
2. ‘선택한 분석 자료도 같이 보내기’가 기본입니다. 질문만 보내려면 해당 전송 범위를 바꿉니다.
3. 웹 검색에는 별도로 직접 입력하고 동의한 공개 검색어를 사용합니다.
4. 필요 없는 자료는 시작 전에 첨부 목록에서 제거합니다.

**입력 예시**

비공개 원자료 대신 필요한 열만 정리한 CSV를 사용할 수 있습니다.

**정상 결과**

- 연구 시작 전 선택한 제공사·자료 범위·예산을 확인할 수 있습니다.

**문제가 생겼을 때**

- 외부 전송을 허용할 수 없으면 시작하지 마세요. 로컬 서버도 실제 외부 전송 차단 검사와 모델 기능 확인이 필요합니다.

## 5. 모델·성능·비용

### 모델의 활성화와 선택

**준비물**

- 같은 제공사의 API 연결을 저장합니다.

**실제 조작**

1. 모델과 예산 장에서 제공사 이름과 모델 이름을 확인합니다.
2. 활성화 모델을 선택합니다. 더보기에서 지원 모델을 제공사별로 펼칩니다.
3. 모델을 바꾸면 다음 작업의 입력·출력 단가와 지원 기능을 확인합니다.
4. 로컬 수동 모델은 설정의 문제 해결 정보에서 실제 서버의 모델 ID·단가·프로토콜을 등록합니다.

**입력 예시**

연결됨: 키·설정 준비. 활성화: 선택 가능한 연결이 있음. 연결 확인 완료: 직접 실행한 검사 성공.

**정상 결과**

- 선택한 모델과 연결이 구분됩니다. 실제 응답 여부는 별도 연결 검사로 확인합니다.

**문제가 생겼을 때**

- 모델이 없거나 접근 불가이면 철자·제공사·계정 권한을 확인하고 접근 가능한 다른 모델을 선택합니다.
### low·medium·high·max

**준비물**

- 처음에는 medium 기본값을 사용해도 됩니다.

**실제 조작**

1. 슬라이더를 움직이거나 키보드 방향키를 눌러 수준을 선택합니다.
2. 슬라이더 아래의 현재 단계 low·medium·high·max를 확인합니다.
3. 높은 단계는 더 많은 실험·검토를 허용할 수 있어 시간과 비용이 늘어날 수 있습니다.
4. 성능 단계와 모델 자체의 추론 설정은 별개입니다. 추론은 고급 설정에서 바꿉니다.

**입력 예시**

첫 연결·작은 질문은 low 또는 medium으로 시작해 결과를 확인합니다.

**정상 결과**

- 현재 단계만 슬라이더 아래에 표시됩니다. 고급 설정을 직접 바꾸면 해당 값이 우선할 수 있습니다.

**문제가 생겼을 때**

- max를 선택해도 자료 부족·지원하지 않는 방법·검증 실패가 자동 해결되지는 않습니다.
### 웹 검색과 공개 검색어

**준비물**

- 외부에 공개해도 되는 검색어를 준비합니다.

**실제 조작**

1. 웹 검색을 자동·허용·사용 안 함 중에서 선택합니다.
2. 검색어에는 공개 자료명·주제·기간을 입력하고 공개 검색어 전송에 동의합니다.
3. 질문 원문·키·비공개 파일을 검색어에 넣지 않습니다.
4. 기본 설정은 남은 예산과 필수 작업 비용을 고려해 검색 횟수를 조정합니다.

**입력 예시**

공개 검색어: NASA GISTEMP global annual temperature anomaly

**정상 결과**

- 검색 제공사 설정·전송 동의·예산을 통과할 때만 검색합니다. 검색 상태와 출처 기록을 확인합니다.

**문제가 생겼을 때**

- 검색 설정이 없거나 자료를 찾지 못하면 실패 상태를 읽어 주세요. 검색 결과를 실제로 확인하지 않고 찾았다고 표시하지 않습니다.
### 예산과 실제 비용 읽기

**준비물**

- 제공사 API 이용 조건과 설정의 월간 한도를 확인합니다.

**실제 조작**

1. 이번 연구 예산을 USD(미화 달러)로 입력합니다.
2. 예산 자동 조정을 켜면 필수 검증·마무리에 필요한 비용을 남기고 선택 작업을 줄입니다.
3. 모델 비용은 입력·출력량과 단가, 웹 검색 비용은 별도 검색 단가로 계산됩니다.
4. 사용량에서 확정 비용·확보한 금액·미확정 비용을 구분해서 봅니다.

**입력 예시**

이번 연구 상한 $0.10은 목표 가격이나 성공 보장이 아니라 앱의 요청 허용 한도입니다.

**정상 결과**

- 버튼에 이번 작업의 한도가 표시됩니다. 더 작은 월간·요청별 제한도 함께 적용됩니다.

**문제가 생겼을 때**

- 제공사 청구·잔액은 제공사 화면에서도 확인하세요. 비용 미확정 상태에서는 중복 요청하지 말고 문제 해결 정보를 확인합니다.

**더 알아보기**

- 토큰은 AI가 처리하는 글 조각입니다. 질문·자료의 입력 토큰과 답·추론의 출력 토큰 단가가 다를 수 있습니다. 단어 수와 토큰 수가 항상 같지는 않습니다.

## 6. 고급 설정

### 역할별 모델 구성

**준비물**

- 모르면 고급 설정을 바꾸지 않아도 됩니다.

**실제 조작**

1. 최상위·중간·하위 그룹에서 각 담당 역할의 모델을 확인합니다.
2. 연구 총괄은 계획을 검토하고, 실험 조정은 작업을 나누며, 분석 담당은 분석 계획, 검토 담당은 결과 검토를 맡습니다.
3. 역할별로 다른 모델을 고르면 해당 제공사 연결도 필요합니다.
4. 현재 지원하는 고정 역할 구조 안에서 선택합니다. 역할 개수를 임의로 추가하는 기능은 아닙니다.

**입력 예시**

처음에는 모든 역할에 기본 선택 모델을 사용합니다.

**정상 결과**

- 역할별 모델을 따로 고르지 않아도 기본 설정으로 시작할 수 있습니다.

**문제가 생겼을 때**

- 역할 모델 필요 오류가 나오면 빠진 역할을 채우거나 기본 선택으로 되돌리세요.
### 추론과 실행 상한

**준비물**

- 선택한 모델이 추론 설정을 지원하는지 확인합니다.

**실제 조작**

1. 고급 설정에서 추론 수준을 선택합니다. 모르면 제공사 기본값을 유지합니다.
2. 추론은 모델이 답을 준비하는 설정이며 연구 성능 단계와 다릅니다.
3. 실행 시간·모델 요청 수·출력 상한은 필요할 때만 줄이거나 조절합니다.
4. 추론·출력·실험 상한이 커지면 비용이 늘 수 있습니다.

**입력 예시**

medium 연구 성능에 추론은 제공사 기본값으로 둡니다.

**정상 결과**

- 지원되는 설정만 실제 요청에 반영되고 현재 단계가 표시됩니다.

**문제가 생겼을 때**

- 지원하지 않는 옵션 오류가 나오면 모델 기본값으로 바꾸고 지원 기능을 확인합니다.
### 검증 항목 3개의 차이

**준비물**

- 기본 필수 검증은 유지됩니다. 아래 세 항목은 기본값이 사용 안 함인 추가 기능입니다.

**실제 조작**

1. 화면의 가벼운 순서대로 분석 도구 검사 → Ridge 수치 검사 → F3-P 오류 복구를 읽습니다.
2. 분석 도구 검사는 고정 분석 도구의 결과·출처를 검사합니다.
3. Ridge 수치 검사는 계수·절편·예측값을 다시 계산합니다. F3-P를 켠 경우에만 선택할 수 있습니다.
4. F3-P 오류 복구는 실패한 분석의 범위가 정해진 수정·재실행·검증을 수행합니다. 추가 모델 호출이 생길 수 있습니다.

**입력 예시**

첫 연구는 세 항목을 모두 끈 기본 설정으로 시작할 수 있습니다. Ridge만 단독으로 켤 수는 없습니다.

**정상 결과**

- 각 항목의 차이와 의존 조건을 확인합니다. 추가 기능을 꺼도 기존 필수 검증·보안 검사는 유지됩니다.

**문제가 생겼을 때**

- Ridge 선택이 비활성화이면 F3-P 필요 조건을 확인하세요. 기능을 켜도 과학적 타당성·모든 오류의 수정이 보장되지는 않습니다.
### 분석 기능과 시작 전 확인

**준비물**

- 고급 설정은 건너뛰어도 됩니다.

**실제 조작**

1. 검증된 분석 도구, F3-P 분석 복구, 실험적 Ridge 검사는 필요할 때만 켭니다. 기본값은 사용 안 함입니다.
2. F3-P는 범위가 정해진 오류의 수정·재검증을 돕습니다. 모든 오류의 자동 수정은 아닙니다.
3. Ridge 검사는 지정된 산술 결과의 일치를 확인하며 과학적 타당성을 보장하지 않습니다.
4. 마지막 장에서 모델·자료·비용을 확인한 뒤 연구 시작을 직접 누릅니다.

**입력 예시**

처음에는 실험 기능을 모두 끈 기본 설정을 사용합니다.

**정상 결과**

- 필수 설정이 준비되면 연구 시작 버튼을 사용할 수 있습니다. 이 안내의 다음은 시작 버튼을 누르지 않습니다.

**문제가 생겼을 때**

- 시작이 막히면 표시된 연결·예산·자료·검증 준비 항목부터 수정하세요.

3. 중단은 연구 진행을 끝내고 저장된 근거·부분 결과를 남깁니다.

**입력 예시**

**정상 결과**

**문제가 생겼을 때**

3. 비용 확인 필요이면 원장·문제 해결 정보를 확인하고 새 요청을 반복하지 않습니다.
4. 예산 부족이면 현재 한도에서 마무리하거나 허용된 예산 변경을 선택합니다.

**입력 예시**

**문제가 생겼을 때**

## 8. 결과 확인하기

### 결론과 근거 읽기

**준비물**

**실제 조작**

3. 자료 근거에서 원본 해시·선택 관측값·다른 형식의 대조 상태를 확인합니다.
4. 이전 결론은 현재 결과와 구분해서 읽습니다.

**입력 예시**

‘두 기간 평균이 다름’과 ‘무엇 때문에 변함’은 서로 다른 주장입니다.

**정상 결과**

- 현재 검증된 범위와 남은 한계가 함께 표시됩니다.

**문제가 생겼을 때**

- 자료 부족·분석 불일치·현재성 만료이면 현재 결론으로 내보내지 않고 필요한 재확인을 진행합니다.
### 질문·자료가 바뀌면 다시 확인

**준비물**

- 지원하는 고정 분석 결과가 있는 연구를 선택합니다.

**실제 조작**

1. 질문 변경으로 비교 범위가 바뀌면 먼저 변경을 저장합니다.
2. 자료 변경 확인으로 사용한 공개 원본이 달라졌는지 확인합니다.
3. 계산 다시 확인하기를 눌러 지원 범위의 로컬 계산을 다시 수행합니다.
4. 재확인 전에는 이전 결론을 현재 결과로 내보낼 수 없습니다.

**입력 예시**

비교 기간을 바꾸면 이전 평균을 새 질문의 결과로 쓰지 않습니다.

**정상 결과**

- 재확인 대기와 새 현재 결론을 구분하며 변경 내역·이전 결과가 보존됩니다.

**문제가 생겼을 때**

- 로컬 계산 재현은 과학적 참을 보장하지 않습니다. 지원하지 않는 질문 변경은 새 분석이 필요할 수 있습니다.
### 보고서 보기와 PDF 저장

**준비물**

- 현재 검증된 결론을 준비합니다.

**실제 조작**

1. 보고서 탭에서 보고서 보기로 본문을 확인합니다.
2. 쉬운 설명은 질문·핵심 결과·한계를 먼저 읽도록 정리한 형식입니다.
3. 기술 보고서는 분석 방법·검증·근거·재현 기록을 자세히 포함합니다.
4. PDF 보고서 만들기를 직접 눌러 다운로드 위치에 저장합니다.

**입력 예시**

보고서 보기는 검증된 본문 미리보기입니다. PDF 페이지 배치를 그대로 보여주는 기능은 아닙니다.

**정상 결과**

- 다운로드 파일은 실제 PDF이며 현재성·무결성 검사를 통과한 내용입니다.

**문제가 생겼을 때**

- 질문 변경 후 차단이면 계산을 다시 확인하세요. PDF 생성기·한글 글꼴·저장 경로 오류는 해당 문제 해결 항목을 확인합니다.
### 내보내기와 재현

**준비물**

- 검증을 통과한 현재 연구 기록이 필요합니다.

**실제 조작**

1. 자세히 보기의 보고서에서 검증 후 내보내기를 선택합니다.
2. 묶음에는 보고서·자료·manifest·재현 안내가 포함됩니다.
3. 다른 환경에서는 재현 안내의 명령과 필요한 실행 환경을 확인합니다.
4. 해시 불일치·빠진 근거·비밀값이 있으면 내보내기가 차단됩니다.

**입력 예시**

**문제가 생겼을 때**

4. 원인을 바꾼 뒤 필요한 검사를 본인이 다시 실행합니다.

**입력 예시**

PROVIDER_AUTH → 키·프로젝트 확인. PROVIDER_SPEND_LIMIT → 제공사 잔액·한도 확인.

**정상 결과**

**문제가 생겼을 때**

- 같은 오류가 반복되면 설정의 문제 해결 정보에서 진단을 확인하세요. 비밀값을 질문이나 오류 보고에 붙이지 않습니다.

3. 저사양 모드는 동시에 처리하는 작업과 기록 조회량을 줄입니다.
4. 기본값 복원은 개인 표시 설정을 초기화합니다. 연구·키·파일은 삭제하지 않습니다.

**입력 예시**

설명은 튜토리얼에서 읽고 평소 연구 화면은 간결하게 사용할 수 있습니다.

**정상 결과**

- 기본 화면의 설명 선호와 학습 진행은 별도로 관리됩니다.

**문제가 생겼을 때**

**준비물**

- 모델을 저장할 공간과 모델 실행에 필요한 메모리·장비를 확인합니다.
- 사용할 도구를 LM Studio 또는 Ollama 중에서 선택합니다.

**실제 조작**

1. 아래 공식 설치 파일 받기를 눌러 LM Studio의 설치 화면을 엽니다.
2. 현재 운영체제에 맞는 설치 파일을 받아 설치하고 실행합니다.
3. 설치한 도구에서 내 장비에서 실행할 수 있는 로컬 모델을 찾습니다.
4. 클라우드 계정·결제·API 키 발급 대신 내 기기의 모델과 서버를 준비합니다.

**입력 예시**

사용할 도구: LM Studio
앱에서 사용할 주소 예시: http://127.0.0.1:1234/v1

**정상 결과**

- 선택한 로컬 도구가 실행되고 모델을 준비할 수 있는 화면이 보입니다.
- 클라우드 API 키를 만들지 않고 다음 단계로 갈 수 있습니다.

**문제가 생겼을 때**

- 설치가 되지 않으면 공식 설치 조건과 운영체제·메모리·저장 공간을 확인합니다.
- 원격 모델을 고르면 외부 요청·계정·요금 조건이 생길 수 있으므로 로컬 모델과 구분합니다.

**더 알아보기**

- 설치·다운로드는 공식 도구에서 직접 수행합니다. 이 앱이 모델 파일을 자동 설치하지 않습니다.

#### 로컬 모델과 서버 준비하기

**준비물**

5. 무인증 로컬 서버에는 클라우드 API 키가 필요하지 않습니다. 인증을 켠 서버는 그 서버의 인증 조건을 따릅니다.

**입력 예시**

LM Studio 서버 주소 예시: http://127.0.0.1:1234/v1

**문제가 생겼을 때**

**더 알아보기**

## 오류별 해결

### API 키 인증 실패

오류명: `401` · `PROVIDER_AUTH` · `CREDENTIAL_UNCONFIGURED`

키가 없거나 잘못됐거나 폐기·만료되었습니다.

다음 조치: 제공사와 프로젝트를 확인하고 키 교체에 새 키를 저장하세요. 그 뒤 모델을 선택하고 연결을 직접 검사하세요.

### 모델·계정 권한 부족

오류명: `403` · `PROVIDER_PERMISSION`

키가 해당 모델·프로젝트를 사용할 권한이 없거나 지역 제한이 있습니다.

다음 조치: 제공사 Console에서 모델·프로젝트 권한과 지원 지역을 확인하세요. 허용되는 모델로 변경하세요.

### 잔액·지출 한도 부족

오류명: `402` · `insufficient_quota` · `PROVIDER_SPEND_LIMIT`

제공사 잔액·결제·지출 한도에 문제가 있습니다.

다음 조치: 제공사 결제 화면에서 잔액·API 이용 조건을 확인하세요. 충전 여부는 직접 결정하세요. 앱 예산과 별도입니다.

### 일시적인 요청 제한

오류명: `429` · `PROVIDER_RATE_LIMIT` · `RATE_LIMITED`

짧은 시간의 요청 수가 제한되었습니다. 429가 잔액 부족을 의미할 수도 있습니다.

다음 조치: 오류의 잔액·한도 정보를 먼저 확인하세요. 일시적 제한이면 안내된 대기 후 한 번 다시 검사하세요.

### 모델 없음·비활성화

오류명: `MODEL_NOT_FOUND` · `CONNECTION_REQUIRED` · `PRIMARY_MODEL_REQUIRED` · `404`

모델 ID·연결·접근 권한이 일치하지 않거나 사용 가능한 연결이 없습니다.

다음 조치: 같은 제공사의 키·연결 사용·전송 설정을 확인하고 활성화 모델을 선택하세요. 수동 모델은 실제 모델 ID를 확인하세요.

### 키 저장 실패

오류명: `SECRET_READBACK_FAILED` · `SECRET_ACL_UNVERIFIED` · `SECRET_ACL_UNSAFE` · `SECRET_PATH_UNSAFE` · `SECRET_FILE_INVALID` · `SECRET_INPUT_INVALID`

키 형식이나 안전 저장소·Windows 로그인 세션을 확인할 수 없습니다.

다음 조치: 키 앞뒤 공백·복사 누락을 확인하고 현재 Windows 사용자로 앱을 다시 실행하세요. 문제 해결 정보의 저장소 오류를 확인하세요. 보안을 끄거나 키를 공개 파일에 저장하지 않습니다.

### 앱 예산 부족

오류명: `BUDGET_BLOCKED` · `BUDGET_EXHAUSTED` · `BUDGET_CAP_REQUIRED`

앱의 월간·연구·요청별 한도 또는 필수 작업 예산을 초과합니다.

다음 조치: 사용량에서 확보·확정·미확정 비용을 확인하세요. 현재 한도에서 마무리하거나 허용된 예산 변경을 직접 선택하세요.

### 비용 미확정·응답 지연

오류명: `NEEDS_RECONCILIATION` · `USAGE_MISSING` · `PROVIDER_TIMEOUT`

### 로컬 서버·인터넷 연결 실패

오류명: `SERVER_UNAVAILABLE` · `NETWORK_ERROR`

서버 미실행·주소·방화벽·인터넷 상태를 확인해야 합니다.

오류명: `CAPABILITY_NOT_VALIDATED` · `INVALID_REQUEST` · `LOCAL_EGRESS_NOT_VALIDATED`

다음 조치: 문제 해결 정보의 모델 상세와 기능별 검사를 확인하세요. 지원하지 않는 옵션은 기본값으로 되돌리세요. 직접 선언은 실제 실행 검증을 대신하지 않습니다.

## 맞춤 연구 설계

첫 장 위에서 맞춤 연구 설계를 선택합니다. 모든 항목은 선택 사항이며 아는 내용만 적습니다.

간단히 보기는 화면만 접습니다. 상세 조건은 계속 적용됩니다. 새 연구에는 이전 조건을 자동으로 적용하지 않습니다.

상세 조건 지우기는 확인 후 상세 입력만 제거합니다. 주제·질문·첨부·실행 설정은 유지됩니다.

항목 추가에서 이름과 역할을 적고 측정·단위·자료 연결을 펼칩니다. 원본 CSV와 열을 선택하여 현재 해시에 연결합니다.

항목·가설·기간·진행 순서는 위로·아래로·삭제로 관리합니다. 접근 방식을 바꾸어 보류한 항목은 역할을 확인한 뒤 다시 적용합니다.

모름·없음·해당 없음은 서로 다릅니다. 해당 없음에는 이유가 필요합니다. 대상 수와 반복 측정, 파일 행 수는 구분합니다.

같게 유지할 조건에는 값·유지 방법·확인 방법·허용 차이·어려운 점을 기록할 수 있습니다. 입력만으로 통제 완료가 되지는 않습니다.

내용에서 항목 정리하기는 원문에 직접 표시된 항목만 로컬로 제안합니다. 선택한 제안 적용 전에는 입력을 덮어쓰지 않습니다. 입력이 달라지면 다시 정리합니다.

입력 내용 확인에서 기간·역할·방법의 충돌을 확인합니다. 자료의 단위·기준과 다르면 원본을 바꾸지 않으며 해당 계산을 보류합니다.

실행 중 조건을 바꾸려면 먼저 일시정지합니다. 연구 조건에서 저장한 변경은 관련 결과를 무효화하며 현재 조건으로 다시 검증해야 합니다.

실제로 지원하지 않는 측정·방법·선택 기준은 의도로 보존하고 실행 제한을 표시합니다. 직접 실험을 했다는 결과나 측정값을 만들어 넣지 않습니다.
